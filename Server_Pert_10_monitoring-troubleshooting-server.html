Teori Metrik: Load Average, CPU States & Linux OOM Killer
⏱ 08.30 – 09.30 · 60 Menit
▼

📊 Membaca Angka Load Average (1m, 5m, 15m)

Load Average adalah jumlah proses yang sedang berjalan atau menunggu giliran CPU (Runnable state) dan I/O disk (Uninterruptible sleep state).
Aturan Emas: Jika server memiliki 4 Core CPU:
  • Load Average = 2.00 → CPU terpakai 50% (Sangat Sehat)
  • Load Average = 4.00 → CPU terpakai 100% (Kapasitas Maksimal)
  • Load Average = 8.00 → Server overload 200% (Ada 4 proses antre macet!)

💀 Linux Kernel Out-Of-Memory (OOM) Killer

Saat RAM fisik dan SWAP habis total (0 bytes available), kernel Linux akan mengaktifkan mekanisme proteksi OOM Killer untuk membunuh proses dengan skor oom_score tertinggi secara paksa (biasanya MySQL atau Apache) agar sistem operasi induk tidak panik/crash!

Praktikum Mandiri — Simulasi Beban Kerja Ekstrem (150 Menit)
⏱ 10.45 – 13.15 · 150 Menit (3,5 JP)
▼
🎯 Target: Siswa menginjeksikan beban CPU/RAM via stress-ng, memantau dampaknya di htop, dan mematikan proses nakal secara aman.
1
Install tools pemantauan performa:
sudo apt update && sudo apt install -y htop sysstat iotop stress-ng
2
Buka 2 Terminal Berdampingan (Terminal 1 = Monitor, Terminal 2 = Attacker):
# Di Terminal 1: Jalankan htop interaktif
htop
3
Di Terminal 2: Simulasikan beban 100% CPU selama 60 detik:
stress-ng --cpu 2 --timeout 60s --metrics-brief
4
Amati grafik CPU di Terminal 1 berubah merah pekat (100% usage)!
5
Simulasikan beban RAM mendekati limit (Memory Leak):
stress-ng --vm 2 --vm-bytes 1G --timeout 45s
6
Membunuh proses yang hang menggunakan sinyal terminasi:
# 1. Sinyal Halus (Graceful Shutdown)
sudo kill -15 [PID_Proses]

# 2. Sinyal Paksa Keras (Jika tidak merespons)
sudo kill -9 [PID_Proses]
