1 Skenario & Alur Pembelajaran Tatap Muka (9 JP / 405 Menit)

Fase 1: Pendahuluan & Konsep SLA (Service Level Agreement) 08.00 - 08.30 (30 Menit)

Apersepsi: Mengapa tim IT Operations (SysAdmin) wajib memonitor server sebelum pengguna mengeluh? Memahami parameter SLA 99.9% uptime, arti metrik Load Average 1.0 vs 4.0 pada CPU 4-core, dan bahaya Swap thrashing.

Fase 2: Utilitas Monitoring CLI Esensial (htop, vmstat, iostat, ss) 08.30 - 09.30 (60 Menit)

Demonstrasi praktis membaca output: (1) htop untuk mengidentifikasi proses rakus CPU/Memory, (2) vmstat 1 5 untuk mengecek antrian proses (r) dan memory swap (si/so), (3) iostat -xz 1 untuk memeriksa %util hard disk, (4) ss -tulnp untuk melihat port listening dan daemon pemiliknya.

Fase 3: Analisis Berkas Log Sistem & journalctl Filtering 09.30 - 10.30 (60 Menit)

Pembedahan filter log canggih: journalctl -u [service] -e -f (follow live output), journalctl -p err..emerg (hanya tampilkan pesan error kritis), serta lokasi berkas log standar di /var/log/auth.log, /var/log/syslog, dan /var/log/nginx/.

Istirahat Lab / Coffee Break 10.30 - 10.45 (15 Menit)

Persiapan skrip stress test beban kerja CPU dan memori.

Fase 4: Job Sheet Praktikum Mandiri — Simulasi Stress Testing & Audit 10.45 - 13.15 (150 Menit)

Siswa mengerjakan Job Sheet 10: (1) Install htop sysstat stress-ng, (2) Menjalankan stress test 100% CPU 4-worker selama 60 detik (stress-ng --cpu 4 --timeout 60s), (3) Mengamati perubahan Load Average di htop, (4) Mengaudit seluruh port terbuka di server (ss -tulnp), (5) Menyusun dokumen audit kesehatan server lengkap dengan rekomendasi tuning.

Fase 5: Skenario Troubleshooting: OOM Killer & Zombie Process 13.15 - 14.15 (60 Menit)

Siswa mendiagnosis kasus: Linux Kernel Out-Of-Memory (OOM) Killer yang mematikan service database spontan akibat RAM habis, serta cara menemukan dan mengeliminasi proses Zombie/Defunct.

Fase 6: Evaluasi Akhir CBT & Refleksi 1 Semester Ganjil 14.15 - 15.00 (45 Menit)

Pengerjaan evaluasi teori komprehensif CBT 30 menit, checklist pengujian audit oleh guru, serta penutupan pembelajaran Semester Ganjil Kelas XII TKJ.

2 Perintah CLI Monitoring Kinerja & Analisis Log

# 1. Monitoring Socket & Port Listening Aktif (Pengganti netstat) sudo ss -tulnp # -t: TCP, -u: UDP, -l: Listening, -n: Numeric IP:Port, -p: Process Name & PID # 2. Monitoring Penggunaan I/O Disk Secara Real-Time iostat -xz 1 5 # Perhatikan kolom '%util': jika mendekati 100%, disk mengalami bottleneck parah! # 3. Analisis Log Layanan Spesifik (Contoh: Web Server Apache) sudo journalctl -u apache2 -n 50 --no-pager # 4. Stress Test Beban Kerja CPU & Memori stress-ng --cpu 2 --vm 1 --vm-bytes 512M --timeout 30s --metrics-brief

4 Laboratorium Troubleshooting: Kernel OOM Killer & High I/O Wait

# KASUS: Service MySQL tiba-tiba mati sendiri tanpa ada yang mematikan # Diagnosa via dmesg / journalctl: sudo dmesg -T | grep -i "oom-killer" # Output: "Out of memory: Killed process 3421 (mysqld) total-vm:2048500kB, anon-rss:980200kB" # Solusi: Naikkan kapasitas RAM, optimasi parameter innodb_buffer_pool_size MySQL, atau aktifkan file Swap 2GB: sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
