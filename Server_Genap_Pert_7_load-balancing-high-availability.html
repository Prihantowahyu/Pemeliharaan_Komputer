1
Pendahuluan — Skalabilitas Vertikal (Scale-Up) vs Horisontal (Scale-Out)
⏱ 08.00 – 08.30 · 30 Menit
▼

Menambah RAM server tunggal (Scale-Up) memiliki batasan hardware dan biaya sangat mahal. Strategi modern adalah Scale-Out (Horisontal): menggabungkan 3-5 server web murah di belakang sebuah Load Balancer sehingga trafik pengunjung dibagi rata secara cerdas!

2
Algoritma Distribusi Beban: Round Robin, Leastconn & IP Hash
⏱ 08.30 – 09.30 · 60 Menit
▼
AlgoritmaCara Kerja DistribusiSkenario Ideal
Round RobinMembagikan request bergantian berurutan: Server 1 → Server 2 → Server 1 → ...Spesifikasi hardware seluruh backend sama persis
Least ConnectionsMengarahkan request ke server yang memiliki antrean koneksi aktif paling sedikitRequest dengan durasi proses lama (Upload video/laporan)
IP HashIP client dihitung hash-nya untuk selalu diarahkan ke server backend yang sama (Session Sticky)Aplikasi web lama tanpa shared session Redis
3
Bedah File Konfigurasi /etc/haproxy/haproxy.cfg
⏱ 09.30 – 10.30 · 60 Menit
▼ 
# Frontend: Pintu masuk dari browser client
frontend http_front
    bind *:80
    mode http
    default_backend http_nodes

# Backend: Daftar server pemroses nyata
backend http_nodes
    mode http
    balance roundrobin
    server web1 192.168.10.11:80 check
    server web2 192.168.10.12:80 check

# Dashboard Statistik Monitoring:
listen stats
    bind *:8404
    stats enable
    stats uri /monitor
    stats refresh 5s
