1 Algoritma Load Balancing

AlgoritmaCara KerjaKasus Terbaik
Round RobinRequest didistribusikan ke backend secara bergiliran (default Nginx)Backend dengan spesifikasi homogen dan waktu respons seragam
Least ConnectionsRequest dikirim ke backend dengan koneksi aktif paling sedikitRequest dengan durasi bervariasi (API, streaming)
IP HashIP client yang sama selalu diarahkan ke backend yang samaSession-based application yang membutuhkan sticky session
WeightedBackend dengan spesifikasi lebih tinggi mendapat porsi traffic lebih besarBackend heterogen (server A 2× lebih kuat dari server B)

2 Konfigurasi Nginx Load Balancer

# /etc/nginx/sites-available/loadbalancer.conf upstream backend_pool { least_conn; # Algoritma Least Connections server 192.168.10.11:80 weight=2; # Server A: bobot 2 (lebih kuat) server 192.168.10.12:80 weight=1; # Server B: bobot 1 server 192.168.10.13:80 backup; # Server C: hanya aktif jika A dan B down } server { listen 80; server_name smk.lan; location / { proxy_pass http://backend_pool; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_connect_timeout 5s; proxy_next_upstream error timeout; # Failover otomatis ke backend berikut } }
# Aktifkan konfigurasi Load Balancer sudo ln -s /etc/nginx/sites-available/loadbalancer.conf /etc/nginx/sites-enabled/ sudo nginx -t && sudo systemctl reload nginx # Uji distribusi traffic — jalankan dari client berulang kali for i in {1..10}; do curl -s http://smk.lan | grep "Server ID"; done
