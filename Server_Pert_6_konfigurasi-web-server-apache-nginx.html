🎯 Tujuan Fase Ini

📖 Materi: Alur Request-Response HTTP

Ketika Anda mengetik http://portal.smk.lan di browser, terjadi 6 proses secara berurutan:
#ProsesPenjelasan untuk Siswa
1DNS ResolutionBrowser bertanya ke DNS Server: "IP berapa untuk portal.smk.lan?" → DNS menjawab: "192.168.10.10"
2TCP ConnectionBrowser membuka koneksi TCP (Three-Way Handshake SYN → SYN-ACK → ACK) ke IP 192.168.10.10 Port 80
3HTTP RequestBrowser mengirim teks: GET / HTTP/1.1\r\nHost: portal.smk.lan\r\n\r\n
4Web Server ProsesApache/Nginx membaca header Host:, menemukan Virtual Host yang cocok, membaca file dari DocumentRoot
5HTTP ResponseServer mengirim: HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n[isi HTML]
6RenderBrowser memproses HTML, CSS, JavaScript dan menampilkan halaman web ke layar

🧠 Pertanyaan Pemantik untuk Diskusi Kelas

  • Jika sekolah memiliki 5 website (portal, e-learning, perpustakaan, PMB, keuangan) — apakah kita perlu 5 server fisik yang berbeda? Jawaban: TIDAK! → Virtual Host!
  • Bagaimana satu IP bisa melayani banyak domain berbeda? → Header Host: pada HTTP/1.1
  • Mengapa website sekolah harus pakai PHP? → Karena data nilai siswa, absensi, dan inventaris harus dinamis dari database

Teori Mendalam: Arsitektur Apache2 vs Nginx
⏱ 08.30 – 09.30 · 60 Menit
▼

📖 Perbandingan Arsitektur Internal

Apache2 (httpd)
  • Model: Process/Thread per Request
  • MPM Prefork: 1 proses anak per koneksi (cocok PHP mod)
  • MPM Event: Thread-based, lebih efisien (cocok PHP-FPM)
  • Konfigurasi: Per-direktori via .htaccess
  • Cocok untuk: Shared hosting, CMS WordPress
  • Port default: 80 (HTTP), 443 (HTTPS)
Nginx
  • Model: Asynchronous Event-Driven
  • 1 worker process menangani ribuan koneksi sekaligus
  • Non-blocking I/O: tidak menunggu satu request selesai
  • Konfigurasi: Terpusat di file /etc/nginx/
  • Cocok untuk: Reverse Proxy, Load Balancer, Static files
  • Konsumsi RAM: Lebih rendah dari Apache

📁 Struktur Direktori Konfigurasi Apache2

# Direktori utama konfigurasi Apache2
/etc/apache2/
├── apache2.conf          # Konfigurasi global utama
├── ports.conf            # Port yang di-listen (80, 443)
├── sites-available/      # Semua file VHost tersedia di sini
│   ├── 000-default.conf  # VHost default (harus di-disable)
│   └── portal.conf       # VHost buatan kita
├── sites-enabled/        # Symlink ke site yang AKTIF saja
├── mods-available/       # Semua modul tersedia
└── mods-enabled/         # Modul yang aktif (symlink)

# Direktori utama konfigurasi Nginx
/etc/nginx/
├── nginx.conf            # Konfigurasi global
├── sites-available/      # Semua server block
└── sites-enabled/        # Symlink ke yang aktif

🔗 Konsep PHP-FPM (FastCGI Process Manager)

Mengapa PHP-FPM? Dulu Apache menggunakan mod_php yang menjalankan PHP di dalam proses Apache langsung — ini boros memori. PHP-FPM adalah daemon PHP terpisah yang diakses melalui socket, sehingga lebih efisien dan aman. 
# Alur: Browser → Nginx/Apache → PHP-FPM → Database
Browser → [HTTP Request: /index.php]
    → Apache/Nginx (menerima koneksi TCP)
    → Deteksi file .php → kirim ke PHP-FPM via socket
    → PHP-FPM memproses skrip PHP, query database
    → Kembalikan HTML ke web server
    → Web server kirim HTTP Response ke browser

# Lokasi socket PHP-FPM 8.1
/var/run/php/php8.1-fpm.sock

# Cek status PHP-FPM
sudo systemctl status php8.1-fpm

Konfigurasi Virtual Host & PHP Integration
⏱ 09.30 – 10.30 · 60 Menit
▼

📄 File Virtual Host Apache2 Lengkap

# File: /etc/apache2/sites-available/portal.conf
<VirtualHost *:80>
    ServerName    portal.smk.lan
    ServerAlias   www.portal.smk.lan
    ServerAdmin   admin@smk.lan
    DocumentRoot  /var/www/portal

    # Konfigurasi direktori web
    <Directory /var/www/portal>
        Options       -Indexes +FollowSymLinks   # Larang directory listing!
        AllowOverride All                     # Izinkan .htaccess
        Require       all granted
    </Directory>

    # Konfigurasi PHP-FPM
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/var/run/php/php8.1-fpm.sock|fcgi://localhost"
    </FilesMatch>

    # Log files
    ErrorLog  ${APACHE_LOG_DIR}/portal_error.log
    CustomLog ${APACHE_LOG_DIR}/portal_access.log combined
</VirtualHost>

📄 File Server Block Nginx Lengkap

# File: /etc/nginx/sites-available/portal.conf
server {
    listen       80;
    server_name  portal.smk.lan www.portal.smk.lan;
    root         /var/www/portal;
    index        index.php index.html index.htm;

    # Lokasi default
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # Proses file PHP via PHP-FPM
    location ~ \.php$ {
        include        snippets/fastcgi-php.conf;
        fastcgi_pass   unix:/var/run/php/php8.1-fpm.sock;
        fastcgi_param  SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    # Blokir akses ke file tersembunyi (.git, .env, .htaccess)
    location ~ /\. {
        deny all;
    }

    error_log  /var/log/nginx/portal_error.log;
    access_log /var/log/nginx/portal_access.log;
}

🔑 Direktif Penting yang Wajib Dipahami Siswa

DirektifTipePenjelasan Lengkap
ServerNameApacheDomain utama yang ditangani VHost ini. WAJIB cocok dengan record DNS!
DocumentRootApacheFolder di server yang berisi file website (index.html/php). Harus ada dan punya izin baca.
Options -IndexesApacheTanda minus (-) = nonaktifkan fitur Indexes. Mencegah pengunjung melihat daftar file.
rootNginxSetara DocumentRoot pada Apache. Lokasi file website.
try_filesNginxUrutan file yang dicoba: $uri → $uri/ → fallback ke index.php (untuk framework)
fastcgi_passNginxArahkan request .php ke PHP-FPM via Unix socket atau TCP

Fault Injection — Diagnosa & Perbaikan Error Web Server
⏱ 13.15 – 14.15 · 60 Menit
▼

🔴 Kasus 1: Error 403 Forbidden

ItemPenjelasan
GejalaBrowser menampilkan "403 Forbidden - You don't have permission to access this resource"
PenyebabHak akses folder /var/www/portal tidak memperbolehkan web server membaca file, atau file index.php tidak ada
Diagnosasudo tail -20 /var/log/apache2/portal_error.log → cari baris AH00035 atau AH01276
Solusisudo chown -R www-data:www-data /var/www/portal && sudo chmod -R 755 /var/www/portal

🔴 Kasus 2: Error 502 Bad Gateway

# Gejala: Browser tampilkan "502 Bad Gateway"
# Penyebab: PHP-FPM tidak berjalan atau socket path salah di konfigurasi VHost

# Langkah diagnosa:
sudo systemctl status php8.1-fpm    # Cek apakah PHP-FPM aktif
ls -la /var/run/php/php8.1-fpm.sock  # Cek file socket ada atau tidak
sudo journalctl -u php8.1-fpm -n 30  # Lihat error log PHP-FPM

# Solusi:
sudo systemctl restart php8.1-fpm
sudo systemctl reload apache2

🔴 Kasus 3: PHP Tidak Dieksekusi (Source Code PHP Tampil)

# Gejala: Browser menampilkan teks mentah: <?php echo phpversion(); ?>
# Penyebab: Modul PHP-FPM belum diaktifkan, atau konfigurasi FastCGI salah

# Solusi Apache2:
sudo a2enmod proxy_fcgi setenvif
sudo systemctl restart apache2

# Verifikasi modul aktif:
apache2ctl -M | grep -i fcgi

🔴 Kasus 4: Virtual Host Salah Melayani Domain

# Gejala: portal.smk.lan menampilkan konten elearning.smk.lan atau sebaliknya
# Penyebab: ServerName salah, atau VHost default (000-default.conf) belum di-disable

# Diagnosa — lihat semua VHost aktif:
sudo apachectl -S
# Output: daftar semua VHost beserta port dan ServerName-nya

# Solusi:
sudo a2dissite 000-default.conf
sudo systemctl reload apache2
⚠️ Guru: Skenario Fault Injection untuk Siswa
Saat siswa sudah berhasil, guru secara diam-diam mengubah permission folder: sudo chmod 700 /var/www/portal → siswa harus mendiagnosa sendiri mengapa terjadi 403 dan menemukan solusinya.
