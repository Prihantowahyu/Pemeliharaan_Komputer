01

Capaian & Tujuan Pembelajaran

Sebelum masuk ke praktik, pahami dulu arah tujuannya — supaya setiap langkah troubleshooting yang kalian lakukan hari ini punya alasan yang jelas.

Capaian Pembelajaran (CP)

Peserta didik mampu mendiagnosis dan mengatasi kerusakan/masalah pada software dan sistem operasi secara sistematis, menggunakan tools diagnosa bawaan OS maupun prosedur perbaikan standar industri.

  • 1
    Identifikasi

    Mengidentifikasi gejala masalah software — mulai dari crash, blue screen (BSOD), hingga boot failure — beserta ciri dan kemungkinan penyebabnya.

  • 2
    Diagnosa

    Menggunakan Safe Mode dan tools diagnosa bawaan sistem operasi untuk mempersempit sumber masalah sebelum melakukan perbaikan.

  • 3
    Perbaikan

    Memperbaiki masalah software umum: meng-uninstall program bermasalah, melakukan repair OS, dan memverifikasi bahwa sistem kembali stabil.

03

Gejala Umum Masalah Software & Sistem Operasi

Setiap kerusakan meninggalkan "jejak". Semakin cepat kalian mengenali jejak ini, semakin cepat pula proses diagnosa dilakukan.

Application Crash

Umum

Program tertutup mendadak, membeku (not responding), atau muncul pesan "has stopped working".

PenyebabFile program korup, konflik versi library/DLL, RAM tidak cukup, bug aplikasi.
IndikatorError dialog spesifik, Event Viewer mencatat Application Error.

Blue Screen of Death (BSOD)

Kritis

Layar biru penuh muncul tiba-tiba, sistem otomatis restart, disertai kode berhenti (stop code).

PenyebabDriver hardware bermasalah, RAM rusak, konflik sistem tingkat kernel.
IndikatorStop code seperti MEMORY_MANAGEMENT, IRQL_NOT_LESS_OR_EQUAL.

Boot Failure

Kritis

Komputer menyala tapi gagal masuk ke sistem operasi — berhenti di logo, layar hitam, atau loop restart.

PenyebabBoot sector/MBR rusak, file sistem hilang, kegagalan update Windows.
IndikatorPesan "Operating System not found" atau "Automatic Repair".

System Freeze / Hang

Umum

Seluruh sistem berhenti merespons — mouse dan keyboard tidak bereaksi sama sekali.

PenyebabOverheating, proses background berat, resource habis (RAM/CPU 100%).
IndikatorTask Manager tidak terbuka, LED disk menyala terus-menerus.

Infeksi Malware / Virus

Kritis

Kinerja sistem melambat drastis, muncul pop-up aneh, program berjalan sendiri, atau antivirus mendadak nonaktif.

PenyebabFile dari sumber tidak resmi, flashdisk terinfeksi, unduhan bajakan/crack.
IndikatorProses asing di Task Manager, penggunaan jaringan tinggi tanpa sebab jelas.

Update Failure

Umum

Windows Update gagal terpasang berulang kali, atau sistem stuck di layar "Working on updates".

PenyebabFile update korup, ruang penyimpanan penuh, koneksi terputus saat update.
IndikatorKode error seperti 0x80070002 pada Windows Update.
:(

Your PC ran into a problem and needs to restart.
We're just collecting some error info, and then we'll restart for you.

0% complete

Stop code: MEMORY_MANAGEMENT
What failed: ntoskrnl.exe

Stop CodeKode unik yang menunjuk pada kategori error — kunci utama pencarian solusi.
What FailedNama driver/file yang memicu crash, jika tersedia oleh sistem.
Langkah AwalCatat kode & nama file sebelum restart — dibutuhkan saat masuk Event Viewer.

Stop code BSOD lain yang sering ditemui:

IRQL_NOT_LESS_OR_EQUALDriver mengakses memori dengan cara yang salah — sering karena driver usang.
PAGE_FAULT_IN_NONPAGED_AREAUmumnya menandakan RAM bermasalah atau hard disk mulai rusak.
CRITICAL_PROCESS_DIEDProses inti Windows berhenti tiba-tiba — sering terkait file sistem korup.
KERNEL_SECURITY_CHECK_FAILUREData sistem penting rusak, kadang dipicu oleh malware.
04

Safe Mode & Tools Diagnosa Bawaan OS

Safe Mode menjalankan Windows dengan driver dan layanan minimal — ini "ruang steril" untuk memastikan apakah masalah berasal dari software pihak ketiga atau dari sistem inti.

  • Masuk ke Safe Mode

    Dari layar login, tahan Shift lalu klik Restart → Troubleshoot → Advanced Options → Startup Settings → Restart → tekan 4 untuk Safe Mode.

    msconfig → Boot → Safe boot

  • Uji apakah masalah masih muncul

    Jika masalah hilang di Safe Mode → penyebabnya software/driver pihak ketiga. Jika masih muncul → kemungkinan masalah ada di sistem inti Windows.

  • Gunakan tools diagnosa bawaan sesuai gejala

    Pilih tools yang relevan dari tabel di bawah untuk menelusuri akar masalah lebih dalam.

    • ToolsFungsiKapan Digunakan
    Event Viewereventvwr.msc Mencatat log error, warning, dan aktivitas sistem secara rinci. Setelah crash/BSOD, untuk menemukan penyebab pastinya.
    Task ManagerCtrl+Shift+Esc Memantau penggunaan CPU, RAM, disk, dan menghentikan proses bermasalah. Saat sistem lambat, freeze, atau resource penuh.
    System Restorerstrui.exe Mengembalikan sistem ke titik pemulihan sebelum masalah terjadi. Setelah instalasi update/driver yang menyebabkan error.
    Startup RepairRecovery Environment Memperbaiki file boot secara otomatis. Saat sistem gagal booting sama sekali.
    SFCsfc /scannow Memindai & memperbaiki file sistem Windows yang korup. Saat dicurigai ada file sistem rusak/hilang.
    DISMDISM /Online /Cleanup-Image /RestoreHealth Memperbaiki image sistem yang menjadi dasar kerja SFC. Ketika SFC gagal memperbaiki karena image rusak.
    ⓘ

    Urutan yang direkomendasikan saat file sistem dicurigai korup: jalankan DISM terlebih dahulu untuk memperbaiki image, baru kemudian SFC untuk memindai file sistem.

    04B

    Glosarium Istilah

    Istilah kunci yang akan sering muncul selama praktik hari ini.

    BSODBlue Screen of Death — layar biru error kritis yang memaksa Windows restart.
    MBR / BCDMaster Boot Record / Boot Configuration Data — data yang memberi tahu komputer cara memuat sistem operasi.
    KernelInti sistem operasi yang mengatur komunikasi antara hardware dan software.
    DriverSoftware penghubung antara sistem operasi dan perangkat keras (GPU, printer, dll).
    Safe ModeMode Windows yang hanya memuat driver & layanan penting untuk keperluan diagnosa.
    RegistryBasis data internal Windows tempat pengaturan sistem dan aplikasi disimpan.
    05

    Teknik Perbaikan Software Umum

    Setelah akar masalah ditemukan, saatnya eksekusi perbaikan. Berikut dua teknik paling sering dipakai teknisi di lapangan.

    Uninstall Program Bermasalah

    LangkahSettings → Apps → pilih program → Uninstall, lalu hapus sisa file/registry dengan uninstaller khusus bila perlu.
    Cocok untukAplikasi yang menyebabkan crash tapi sistem OS masih sehat.
    PerhatianRestart setelah uninstall untuk memastikan proses & service terkait benar-benar berhenti.

    Repair / Reset Sistem Operasi

    LangkahSettings → System → Recovery → "Reset this PC" (Keep my files), atau gunakan media instalasi untuk Repair Install.
    Cocok untukKerusakan file sistem inti, boot failure berulang, atau OS sangat tidak stabil.
    PerhatianBackup data penting dahulu — meski opsi "keep files" tersedia, risiko tetap ada.
    06

    Cek Pemahaman (Formatif)

    Sebelum masuk studi kasus, pastikan konsep dasarnya sudah lekat. Klik salah satu opsi untuk melihat apakah jawabanmu benar.

    1. Jika sebuah aplikasi selalu crash tapi sistem berjalan normal di Safe Mode, apa kesimpulan yang paling tepat?

    A Kerusakan pasti ada di RAM fisik
    B Masalah kemungkinan besar dari software/driver pihak ketiga
    C Sistem operasi harus segera diinstal ulang total

    2. Tools apa yang paling tepat digunakan untuk memeriksa penyebab pasti sebuah BSOD setelah komputer restart?

    A Task Manager
    B Event Viewer
    C Disk Cleanup

    3. Ketika file sistem dicurigai korup, urutan perbaikan yang paling tepat adalah...

    A SFC dulu, baru DISM
    B DISM dulu, baru SFC
    C Langsung Reset PC tanpa tools apa pun

    07

    Studi Kasus Troubleshooting

    Terapkan seluruh alur — gejala → Safe Mode/tools → perbaikan — pada dua kasus berikut. Klik tiap kasus untuk melihat pertanyaan pemandu dan kunci pembahasannya.

    KASUS 01

    Laptop mengalami Blue Screen setiap kali membuka aplikasi desain grafis.

    ›

    Skenario: Seorang siswa melaporkan laptopnya selalu blue screen dengan stop code SYSTEM_SERVICE_EXCEPTION tepat setelah membuka aplikasi desain grafis yang baru diinstal minggu lalu.

    Pertanyaan Pemandu
    1. Apa langkah pertama yang harus dilakukan sebelum menyalakan ulang laptop?
    2. Tools apa yang digunakan untuk mengecek log penyebab BSOD tersebut?
    3. Jika penyebabnya adalah driver GPU yang tidak kompatibel, apa langkah perbaikannya?
    1. Catat stop code yang tampil, lalu masuk ke Safe Mode agar aplikasi & driver tambahan tidak dimuat.
    2. Buka Event Viewer untuk melihat detail error dan nama driver yang gagal.
    3. Uninstall/rollback driver GPU melalui Device Manager, lalu install ulang driver versi stabil dari situs resmi produsen.
    KASUS 02

    PC lab sekolah tidak bisa booting setelah mati listrik mendadak.

    ›

    Skenario: Setelah listrik padam mendadak, sebuah PC di lab komputer hanya menampilkan layar hitam dengan tulisan "Automatic Repair couldn't repair your PC" saat dinyalakan kembali.

    Pertanyaan Pemandu
    1. Apa kemungkinan penyebab utama kerusakan ini?
    2. Tools bawaan Windows apa yang relevan untuk kasus boot failure seperti ini?
    3. Susun urutan langkah perbaikan dari yang paling ringan ke paling berat.
    1. Mati listrik mendadak berpotensi merusak file boot (MBR/BCD) yang sedang ditulis saat itu.
    2. Gunakan Startup Repair dari Recovery Environment; jika gagal, lanjut ke Command Prompt untuk perintah bootrec.
    3. Urutan: (1) Startup Repair otomatis → (2) perbaikan boot manual via Command Prompt → (3) System Restore ke titik sebelumnya → (4) Reset/Repair Install jika semua gagal.

    Remedial & Pengayaan

    Tidak semua siswa tuntas di waktu yang sama — berikut tindak lanjut untuk keduanya.

    Remedial
    • Pendampingan ulang praktik masuk Safe Mode secara berpasangan dengan tutor sebaya.
    • Mengerjakan ulang 1 studi kasus dengan tingkat kesulitan yang disederhanakan.
    • Diberi checklist langkah troubleshooting sebagai alat bantu selama praktik.
    Pengayaan
    • Menyusun sendiri 1 studi kasus baru beserta kunci pembahasannya untuk teman sekelas.
    • Mengeksplorasi Command Prompt lanjutan: bootrec, chkdsk, diskpart.
    • Riset singkat perbandingan tools recovery di Windows vs Linux.
