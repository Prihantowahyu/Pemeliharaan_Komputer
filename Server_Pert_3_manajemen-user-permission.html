Manajemen User, Group, File Permission & Hak Akses Sudoers

Menerapkan prinsip keamanan Principle of Least Privilege (PoLP) pada sistem multi-user Linux Server: Manajemen akun user & group departemen, konversi notasi izin oktal (rwx / 755, 644, 700, 2775 SGID), kepemilikan chown/chgrp, serta delegasi hak administratif terbatas menggunakan visudo.

1 Skenario & Alur Pembelajaran Tatap Muka (9 JP / 405 Menit)

Fase 1: Pendahuluan & Studi Kasus Pembobolan Server 08.00 - 08.30 (30 Menit)

Guru memaparkan bahaya menggunakan akun root untuk operasional harian. Pembahasan konsep Principle of Least Privilege (PoLP): Setiap pengguna/layanan hanya boleh memiliki hak akses seminimal mungkin yang diperlukan untuk menjalankan tugasnya.

Fase 2: Struktur Database User Linux (/etc/passwd, /etc/shadow, /etc/group) 08.30 - 09.30 (60 Menit)

Pembedahan 7 kolom pada file /etc/passwd (Username, Password flag 'x', UID, GID, GECOS Info, Home Directory, Default Shell). Eksplorasi enkripsi hash password SHA-512 pada /etc/shadow dan perbedaan perintah useradd (low-level) vs adduser (interactive script).

Fase 3: Notasi Izin Akses Oktal & Special Permission Bits (SUID, SGID, Sticky) 09.30 - 10.30 (60 Menit)

Menghitung kalkulasi biner/oktal (Read=4, Write=2, Execute=1) untuk User, Group, dan Others. Mempelajari bit khusus: SUID (4xxx), SGID (2xxx — pewarisan group folder kolaborasi), dan Sticky Bit (1777 — proteksi file di /tmp agar hanya pemilik yang bisa menghapus).

Istirahat Lab / Coffee Break 10.30 - 10.45 (15 Menit)

Penyegaran dan persiapan login ke terminal server masing-masing.

Fase 4: Job Sheet Praktikum Mandiri — Skenario Struktur Perusahaan 10.45 - 13.15 (150 Menit)

Siswa mengerjakan Job Sheet 3: (1) Membuat 3 group departemen (it_admin, finance, staff), (2) Membuat 6 akun user dengan direktori home terisolasi (chmod 700), (3) Membuat folder bersama /data/finance_shared dengan izin 2770 (SGID) milik group finance, (4) Mengonfigurasi file sudoers delegasi perintah restart web server tanpa password.

Fase 5: Skenario Kasus Gangguan & Sudoers Recovery 13.15 - 14.15 (60 Menit)

Siswa memecahkan masalah: Error "syntax error in /etc/sudoers" yang menyebabkan sudo terkunci (diperbaiki menggunakan recovery mode / pkexec) dan mendiagnosis masalah "Permission Denied" saat web server membaca file index.html.

Fase 6: Evaluasi CBT & Presentasi Hasil Praktik 14.15 - 15.00 (45 Menit)

Evaluasi teori CBT 30 menit, checklist pengujian permission per-kelompok oleh guru, dan pemberian pengantar materi DHCP Server.

4 Laboratorium Troubleshooting: Permission Denied & Sudoers Corrupted

# KASUS 1: Web server Nginx/Apache menampilkan "403 Forbidden" # Gejala: Browser menampilkan error 403 Forbidden saat membuka website. # Diagnosa: ls -l /var/www/html/index.html → -rw------- 1 root root # Solusi Perbaikan: sudo chown -R www-data:www-data /var/www/html sudo find /var/www/html -type d -exec chmod 755 {} \; sudo find /var/www/html -type f -exec chmod 644 {} \; # KASUS 2: Terjadi typo pada file /etc/sudoers sehingga perintah sudo rusak ("syntax error near line...") # Solusi: Jalankan visudo via PolicyKit (pkexec) tanpa perlu akses root langsung: pkexec visudo # Perbaiki baris syntax yang salah, lalu simpan file.
