Driver mencoba mengakses alamat memori yang tidak valid atau memiliki level IRQL yang terlalu tinggi. File pemicu umum: driver grafis (nvlddmkm.sys / amdkmdag.sys), driver WiFi, atau software anti-cheat game.

JP 3-4

JP 5-6

JP 7-8

Bagian A · Metodologi Diagnosa

A. Kerangka Investigasi Berlapis (Layered Troubleshooting Model)

Teknisi profesional tidak menebak-nebak kerusakan. Pendekatan 4 layer memastikan isolasi masalah berlangsung cepat, logis, dan hemat biaya perbaikan.

Layer 1 · Fisik & Elektrikal

Pemeriksaan catu daya (PSU), tegangan jalur 12V/5V/3.3V, kabel power, grounding listrik, kebersihan debu, pasta termal, dan kondisi visual komponen (kapasitor kembung, jalur PCB gosong).

  • Alat: Multimeter Digital, PSU Tester, Obeng Presisi, Kuas ESD.
  • Gejala Khas: Mati total, restart mendadak tanpa log, bau hangus.

Layer 2 · Firmware & BIOS/UEFI

Inisialisasi Power-On Self-Test (POST), pembacaan kode beep speaker, LED debug motherboard, baterai CMOS CR2032, versi mikrokode BIOS, dan konfigurasi boot priority.

  • Alat: POST Card Analyzer, Jumper Clear CMOS, Flashdisk BIOS Flashback.
  • Gejala Khas: No Display, beep code berulang, BIOS reset sendiri.

Layer 3 · Driver & Kernel OS

Interaksi driver perangkat keras dengan kernel Windows (ntoskrnl.exe). Analisis crash dump BSOD, mode Safe Mode, verifikasi sertifikasi driver (WHQL), dan rolling back driver bermasalah.

  • Alat: WinDbg, DDU (Display Driver Uninstaller), Device Manager, Event Viewer.
  • Gejala Khas: BSOD stop code spesifik, freeze saat install driver, layar berkedip.

Layer 4 · Software & Registry

Integritas file sistem Windows (SFC & DISM), konflik software startup, infeksi malware background, korupsi registry Windows, dan service background yang macet.

  • Alat: sfc /scannow, DISM, Task Manager, Autoruns Sysinternals.
  • Gejala Khas: Aplikasi crash, loading lambat, popup error dll/exe.
Bagian B · Debugging Crash Dump

B. Panduan Analisis Crash Dump Windows (.DMP) dengan WinDbg

Ketika Windows mengalami Blue Screen, sistem menyimpan rekam memori saat crash terjadi ke folder C:\Windows\Minidump\. Ini adalah bukti paling akurat untuk menemukan pelaku penyebab crash.

Mengambil File Dump dari Sistem Korban

Akses folder C:\Windows\Minidump\. Cari file dengan ekstensi .dmp terbaru (misal: 081826-14520-01.dmp). Salin file tersebut ke Desktop atau flashdisk teknisi.

Membuka Minidump di Software WinDbg

Buka WinDbg (Windows Debugger) sebagai Administrator → tekan Ctrl + D → pilih file .dmp yang telah disalin tadi.

Menjalankan Analisis Otomatis (!analyze -v)

Pada baris perintah debugger di bagian bawah, klik tautan !analyze -v atau ketik perintah tersebut dan tekan Enter. WinDbg akan mencocokkan simbol Microsoft dan membedah stack trace kernel.

Membaca Baris Modul Penyebab Utama

Cari baris: MODULE_NAME, IMAGE_NAME, dan PROCESS_NAME. Jika tertulis nvlddmkm.sys → Driver GPU NVIDIA. Jika tertulis rtwlane.sys → Driver Realtek WiFi. Jika tertulis ntoskrnl.exe dengan MEMORY_MANAGEMENT → Kerusakan fisik modul RAM.
