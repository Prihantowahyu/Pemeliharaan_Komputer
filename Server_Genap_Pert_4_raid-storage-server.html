Redundant Storage Management (Software RAID 0, 1, 5, 10 & Hot Spare Rebuild)

Panduan industri membangun subsistem penyimpanan data redundan tanpa single point of failure: Membedah arsitektur RAID Level 0 (Striping), RAID 1 (Mirroring), RAID 5 (Distributed Parity), dan RAID 10 (Striped Mirror), implementasi Software RAID Linux via mdadm, alokasi Hot-Spare Drive otomatis, simulasi kegagalan disk fisik dan rekonstruksi data online (Array Rebuild), serta integrasi LVM.

1 Skenario & Alur Pembelajaran Tatap Muka (9 JP / 405 Menit)

Fase 1: Pendahuluan & Risiko Kerusakan Hard Disk Mekis/SSD 08.00 - 08.30 (30 Menit)

Apersepsi: Mengapa server data center tidak boleh hanya mengandalkan 1 unit hard disk? Guru memaparkan statistik kegagalan drive (AFR - Annualized Failure Rate) dan pentingnya toleransi kesalahan (Fault Tolerance) menggunakan RAID.

Fase 2: Komparasi Teknis RAID 0, 1, 5, 6, dan 10 08.30 - 09.30 (60 Menit)

Perhitungan matematis kapasitas efektif: RAID 0 (100% kapasitas, 0% toleransi), RAID 1 (50% kapasitas, toleransi 1 disk mati), RAID 5 ((N-1) kapasitas, toleransi 1 disk mati dengan kalkulasi XOR Parity), dan RAID 10 (kecepatan striping + keandalan mirroring ganda).

Fase 3: Bedah Utilitas mdadm & Konsep Hot-Spare 09.30 - 10.30 (60 Menit)

Pembedahan parameter CLI: mdadm --create /dev/md0 --level=5 --raid-devices=3 --spare-devices=1 /dev/sdb /dev/sdc /dev/sdd /dev/sde dan pemantauan status array di /proc/mdstat.

Istirahat Lab / Coffee Break 10.30 - 10.45 (15 Menit)

Persiapan menambahkan 4 virtual hard disk (masing-masing 5GB) pada VM siswa.

Fase 4: Job Sheet Praktikum Mandiri — Simulasi Disk Crash & Hot-Rebuild 10.45 - 13.15 (150 Menit)

Siswa mengerjakan Job Sheet Genap 4: (1) Buat array RAID 5 dari 3 disk aktif + 1 hot-spare, (2) Format ext4 dan mount ke /data/secure_storage, (3) Salin 1000 file dokumen ke dalamnya, (4) Simulasikan disk rusak: sudo mdadm /dev/md0 --fail /dev/sdb, (5) Pantau proses otomatis hot-spare /dev/sde mengambil alih dan melakukan rebuild parity secara online tanpa ada data yang hilang!

Fase 5: Skenario Kasus Gangguan (Troubleshooting Array Degraded) 13.15 - 14.15 (60 Menit)

Siswa menangani kondisi array [UU_] (Degraded), melepas hard disk rusak dengan --remove, dan memasang hard disk pengganti baru dengan --add.

Fase 6: Evaluasi CBT & Refleksi 9 JP 14.15 - 15.00 (45 Menit)

Pengerjaan evaluasi teori CBT 30 menit, checklist pengujian live rebuild oleh guru, dan pengantar materi Backup & Disaster Recovery.

# 1. Membuat Array RAID 5 dengan 3 Disk Aktif + 1 Disk Hot-Spare sudo mdadm --create /dev/md0 --level=5 --raid-devices=3 --spare-devices=1 /dev/sdb /dev/sdc /dev/sdd /dev/sde # 2. Menyimpan Konfigurasi agar Persisten Pasca Reboot sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf sudo update-initramfs -u # 3. Simulasi Kerusakan Hard Disk Fisik (Fault Injection) sudo mdadm /dev/md0 --fail /dev/sdb cat /proc/mdstat # Mengamati hot spare /dev/sde langsung rebuild menggantikan /dev/sdb!

4 Laboratorium Troubleshooting: State [UU_] Degraded Array

# KASUS: cat /proc/mdstat menampilkan "md0 : active raid5 sdd[2] sdc[1] [3/2] [UU_]" # Analisis: Tanda '_' menunjukkan ada 1 drive yang hilang/mati. Array masih bisa melayani baca-tulis karena kalkulasi parity, tetapi toleransi kesalahan tersisa 0! Segera pasang disk pengganti sebelum drive lain rusak!
